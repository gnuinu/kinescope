# Kinescope

파일을 QR 로 바꿔 **화면에 띄우고, 그걸 찍어서, 원본으로 되살립니다.**
망이 끊긴 곳으로 코드를 옮길 때 쓰는 도구입니다.

키네스코프(kinescope)는 TV 화면을 필름 카메라로 찍어 방송을 보존하던 실제
기법입니다. 이 도구가 하는 일도 같습니다.

```
   보내는 쪽                        찍기                    받는 쪽
┌──────────────┐            ┌──────────────┐         ┌──────────────┐
│ 파일 · 폴더   │  파이썬     │  QR 이 뜬     │  폰      │  Kinescope   │
│      ↓       │ ───────→   │  브라우저     │ ─────→  │  웹페이지     │
│  zip → QR    │  HTML 한 장 │  화면        │ 사진/영상│      ↓       │
└──────────────┘            └──────────────┘         │  원본 파일    │
                                                     └──────────────┘
```

받는 쪽은 **브라우저만** 있으면 됩니다. 서버가 없고, 파일이 어디로도 전송되지
않고, 한 번 열어둔 뒤로는 인터넷 없이도 돕니다.

## 빠른 시작

**보내는 쪽** (파이썬이 있는 컴퓨터에서 한 번만)

```bash
pip install segno
python3 tools/kinescope_encode.py sheet ./내보낼폴더 -o out/
# → out/index.html 이 생깁니다. 더블클릭해서 여세요.
```

**찍기**

브라우저에 뜬 시트를 `F` 키로 머리글까지 숨겨 화면 가득 채우고, 한 장씩
정면에서 찍습니다. `→` 로 다음 시트, 다 찍을 때까지.

**받는 쪽**

Kinescope 페이지를 열고 찍은 사진을 **전부 한 번에** 끌어다 놓습니다.
격자가 다 채워지면 zip 이 나옵니다.

## 시트와 스트림, 어느 쪽을 쓸까

| | **시트** (사진) | **스트림** (동영상) |
|---|---|---|
| 만드는 명령 | `sheet` | `stream` |
| 화면에 | QR 여러 개가 한 판에 | QR 한 개가 계속 바뀜 |
| 찍는 법 | 한 장씩 사진 | 영상 한 번 |
| 빠지면 | **한 조각만 빠져도 실패** | 몇 개 놓쳐도 됨 (파운틴 코드) |
| 다시 찍기 | 빠진 시트만 다시 | 그냥 더 길게 |
| 알맞은 때 | 파일이 작을 때, 확실히 하고 싶을 때 | 파일이 클 때, 손이 편한 게 우선일 때 |

**헷갈리면 스트림**입니다. 조각을 놓쳐도 되고, 영상을 한 번만 찍으면 되고,
"몇 번째 시트를 안 찍었더라" 를 셀 일이 없습니다. 시트는 **한 조각이라도 빠지면
그 시트를 다시 찍어야** 하는 대신, 사진이라 흔들림이 적고 다시 보기 쉽습니다.

Kinescope 는 QR 내용만 보고 둘을 알아서 구분합니다. 고민하지 않아도 됩니다.

## 1. QR 만들기

`tools/kinescope_encode.py` 가 파일이나 폴더를 받아 **자체 완결 HTML** 을
만듭니다. 만든 HTML 은 인터넷도 서버도 필요 없이 더블클릭으로 열립니다.
파이썬은 만드는 쪽에서만 필요합니다.

```bash
pip install segno
```

입력은 **파일이든 폴더든** 됩니다. zip 이 아니면 알아서 묶습니다.

### 시트 만들기

```bash
python3 tools/kinescope_encode.py sheet ./내보낼폴더 -o out/
```

```
내보낼폴더 → zip 49,361 바이트
SHA-256(zip)  6a9f1227f43ca9381c4c3c713b446b2aa4de5a912745ec59cb58d9cd422c3894
QR 66개 · 시트 11장 · QR 버전 23
→ out/index.html 를 브라우저로 여세요
```

`out/index.html` 이 목록이고 `out/sheet_01.html …` 이 각 시트입니다.

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--per-sheet N` | 6 | 한 화면에 넣을 QR 개수. **줄이면 QR 이 커져 훨씬 잘 읽힙니다** |
| `--chunk N` | 1000 | QR 하나에 담을 base64 길이. 키우면 QR 수는 줄지만 촘촘해집니다 |
| `--png` | 꺼짐 | HTML 과 함께 낱장 PNG 도 저장 (인쇄용) |

### 스트림 만들기

```bash
python3 tools/kinescope_encode.py stream ./내보낼폴더 -o out/
```

```
블록 97개 · 패킷 214개 · QR 버전 16
→ out/stream.html 를 브라우저로 열고 재생하면서 찍으세요 (2.2MB)
```

`out/stream.html` 하나만 나옵니다. 열면 바로 재생됩니다.

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--fps N` | 10 | 재생기 기본 속도. 화면에서 슬라이더로 바꿀 수도 있습니다 |
| `--block N` | 512 | 블록 크기(바이트). 키우면 QR 이 촘촘해지고 개수는 줍니다 |
| `--overhead N` | 2.2 | 블록 수 대비 패킷 배수. **여유분입니다** — 늘리면 한 바퀴가 길어지는 대신 놓쳐도 안전합니다 |
| `--seed N` | 무작위 | 같은 결과를 다시 만들고 싶을 때 |
| `--png` | 꺼짐 | 프레임 PNG 도 저장 (ffmpeg 로 동영상을 만들 때) |

### 크기 감각

49KB zip(파이썬 소스 3개) 기준입니다.

| | 결과 | 찍는 데 걸리는 시간 |
|---|---|---|
| 시트 (기본값) | QR 66개 · **시트 11장** | 사진 11장 |
| 시트 `--chunk 1400` | QR 48개 · 시트 8장 | 사진 8장 (QR 은 더 촘촘) |
| 스트림 (기본값) | 패킷 214개 · 10fps | 한 바퀴 **21초**, 두 바퀴면 넉넉 |

파일이 커질수록 스트림이 유리합니다. 시트는 사진 수가 그대로 늘어나지만,
스트림은 재생 시간만 늘어납니다.

## 2. 화면에 띄우고 찍기

### 공통

- **화면을 가득 채우세요.** `F` 키를 누르면 머리글과 단추가 사라져 QR 이
  더 커집니다. 브라우저 전체화면(F11)도 같이 쓰면 더 좋습니다
- 화면 밝기를 올리고, 화면에 비치는 반사광(조명·창문)을 피하세요
- **초점**이 제일 중요합니다. 흔들림보다 초점이 나간 게 더 치명적입니다
- 화면 전체가 프레임 안에 들어오게, 가급적 정면에서

### 시트 (사진)

1. `out/index.html` 을 열고 첫 시트로 들어갑니다
2. `F` 로 머리글을 숨기고, 화면 가득 찬 QR 들을 한 장 찍습니다
3. `→` 키로 다음 시트, 반복
4. **시트 번호를 세면서 찍으세요.** 순번 방식이라 한 장이라도 빠지면 복원이
   안 됩니다 (다행히 Kinescope 가 몇 번이 빠졌는지 알려줍니다)

찍은 사진은 **전부 한 번에** 넣습니다. 순서는 상관없습니다.

### 스트림 (동영상)

1. `out/stream.html` 을 열면 바로 재생됩니다. `F` 로 화면을 비웁니다
2. 동영상 촬영을 시작하고, **한 바퀴 반 ~ 두 바퀴** 정도 찍습니다
   (화면 아래에 "37 / 214 · 1바퀴" 로 진행이 표시됩니다)
3. 끝냅니다. 파일 하나만 Kinescope 에 넣으면 됩니다

폰 카메라가 보통 30fps 라, 재생 10fps 면 QR 하나가 3프레임씩 찍힙니다.
넉넉합니다. 초점이 자꾸 흔들리면 속도를 6~8fps 로 낮추세요.

## 3. 되살리기

Kinescope 페이지를 엽니다. 넣는 방법은 세 가지입니다.

- **끌어다 놓기 / 파일 선택** — 동영상이든 사진이든, 여러 개를 한 번에
- **카메라로 비추기** — 파일을 만들지 않고 화면을 직접 비춥니다.
  다 모이는 순간 알아서 멈춥니다 (HTTPS 나 localhost 에서만 됩니다)
- 스캔 도중 **중지하고 조립** — 멈춰도 버리지 않고 그때까지 모은 조각으로
  조립을 시도합니다. 생각보다 자주 성공합니다

### 화면 읽는 법

가운데 **격자**가 블록 복원 현황입니다. 한 칸이 원본 조각 하나이고, 실제로
풀린 칸만 채워집니다. 스트림에서는 후반부에 우르르 채워지는 게 정상입니다 —
peeling 디코더는 임계점을 넘는 순간 연쇄적으로 풀립니다.

| 계기판 | 뜻 |
|---|---|
| 프레임 | 지금까지 들여다본 화면 수 |
| 패킷 | 읽어낸 QR 개수 (중복 제외) |
| 블록 | 복원된 조각 / 전체 |
| 중복 | 이미 읽은 QR 을 또 읽은 횟수 — 높아도 문제없습니다 |

복원되면 **SHA-256** 이 표시됩니다. 시트·스트림 화면 머리글에 찍힌 값과
같으면 원본 그대로입니다. 스트림은 자동으로 대조해 **✓ 체크섬 일치**를 붙입니다.

파일 이름을 누르면 개별 저장, `zip 내려받기` 로 통째로 저장됩니다.

## 잘 안 될 때

| 증상 | 해볼 것 |
|---|---|
| "QR 을 하나도 읽지 못했습니다" | 초점을 확인하세요. QR 이 화면에서 작게 나왔다면 `--per-sheet 4` 로 다시 만드세요 |
| 시트에서 "빠진 조각: 12, 13" | 그 번호가 있는 시트만 다시 찍어 **다른 사진들과 함께** 넣으세요 |
| 스트림에서 블록이 모자람 | 더 길게(두 바퀴 이상) 찍거나, 만들 때 `--overhead 3` 으로 여유분을 늘리세요 |
| 영상인데 진행이 더딤 | 재생 배속을 1~2× 로 낮춰보세요. 그래도 모자라면 앱이 알아서 한 프레임씩 다시 훑습니다 |
| 카메라 단추가 안 먹음 | HTTPS 또는 `localhost` 여야 합니다. 브라우저 주소창의 권한 설정도 확인하세요 |
| `file://` 로 열었더니 아무것도 안 됨 | 앱은 웹서버로 열어야 합니다 (`python3 -m http.server`). **QR 시트·스트림 HTML 은** `file://` 로 열어도 됩니다 |

사진이 잘 안 읽히는 가장 흔한 원인은 **QR 이 화면에서 작았던 것**입니다.
`--per-sheet` 를 줄이는 게 거의 항상 답입니다.

## 오프라인으로 쓰기

앱을 실행하려면 웹서버가 필요합니다. `file://` 로는 ES 모듈 워커와 wasm
로딩이 막힙니다.

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

첫 방문 때 서비스워커가 페이지·스크립트·wasm 을 통째로 받아둡니다. 그 뒤로는
**망을 끊어도** 주소만 열면 그대로 뜨고, 홈 화면에 설치하면 앱처럼 뜹니다.

> 파일을 고쳤다면 `sw.js` 의 `VERSION` 을 올리세요. 올리지 않아도 캐시로 먼저
> 응답하고 뒤에서 새 파일을 받아두는 구조라 다음 방문 때 갱신되지만,
> `VERSION` 을 올리면 그 자리에서 통째로 갈립니다.

## GitHub Pages 에 올리기

저장소 루트에 그대로 두고 Settings → Pages → Deploy from a branch → 루트(`/`)를
고르면 끝입니다. 주소는 `user.github.io/kinescope/` 가 됩니다.

- 모든 경로가 `import.meta.url` 기준 상대경로라 **서브패스에서도 깨지지 않습니다.**
  실제로 `/kinescope/` 아래에 올려두고 확인했습니다
- 루트의 빈 `.nojekyll` 파일을 지우지 마세요. 이게 없으면 Jekyll 이 일부 경로를
  건드려 `vendor/` 쪽에서 404 가 납니다
- `.wasm` 은 Pages 가 `application/wasm` 으로 서빙합니다. 설령 스트리밍
  인스턴스화가 실패해도 ArrayBuffer 방식으로 자동 폴백합니다
- HTTPS 라 `crypto.subtle` 과 카메라가 정상 동작합니다

## 구조

```
index.html          화면 + 스타일
app.js              파일·카메라 입력, 프레임 추출, 결과 표시
sw.js               오프라인 캐시 (서비스워커)
manifest.webmanifest, icon.png   홈 화면에 설치할 때 쓰는 것들
lib/
  worker.js         워커: QR 디코드 + 조립 (메인 스레드 안 막음)
  lt.js             LT 파운틴 디코더 + 순번 수집기
vendor/
  zxing/            zxing-wasm 3.1.2 (리더 전용, 1.1MB wasm)
  fflate.js         zip 해제
tools/
  kinescope_encode.py   QR 생성기 (시트 HTML · 스트림 재생기 · PNG)
  selftest.mjs          헤드리스 브라우저로 복원까지 돌려보는 회귀 시험
```

**왜 서버가 없는가.** 이 도구가 다루는 게 남의 코드라는 걸 생각하면 업로드받는
설계는 그 자체로 부담이고, 망이 없는 곳에서 쓰는 게 원래 목적이니 서버가 있으면
안 됩니다. 라이브러리를 CDN 이 아니라 `vendor/` 에 넣어둔 것도 같은 이유입니다.

## 안에서 무슨 일이 일어나는가

**두 형식을 QR 내용만 보고 구분합니다.**

| 형식 | QR 본문 | 모으는 방식 |
|---|---|---|
| 스트림 | 바이너리 매직 `QS` | LT 파운틴 — 아무 조각이나 충분히 모이면 됨 |
| 시트 | `QRP001/036:` | 순번 수집 — 번호가 다 있어야 함 |

### 동영상은 두 패스로

1. **재생 패스** — `requestVideoFrameCallback` 으로 재생하며 프레임을 뽑습니다.
   빠르지만 디코더가 못 따라간 프레임은 흘려보냅니다. 대개 이것만으로 끝납니다
2. **훑기 패스** — 재생만으로 모자랐으면 한 프레임씩 seek 하며 다시 훑습니다.
   느린 대신 한 장도 놓치지 않습니다. 프레임 타임스탬프를 보고 같은 프레임은
   두 번 디코드하지 않으므로, 30fps 촬영본에서 10fps 화면을 찍었더라도 헛일이
   없습니다

**충분히 모이는 즉시 멈춥니다.** 20초 영상이라도 중간에 끝나는 경우가 많습니다.

### 사진은 세 번 두드립니다

모니터를 찍은 사진에는 모아레와 JPEG 잡티가 겹칩니다. 4032×3024 사진에 촘촘한
QR(버전 25 이상)이 10장 들어 있으면 한 모듈이 3픽셀도 안 돼서, 한 번에 읽으려
들면 **한 장도 못 읽는 일이 생깁니다.** 그래서 사진은 순서대로 이렇게 봅니다.

1. 사진 그대로 (지역 이진화) — 또렷하면 여기서 끝납니다
2. **2×2로 겹치게 잘라서** 각 조각을 따로 — 촘촘한 QR 이 여기서 대부분 살아납니다
3. 전역 히스토그램 이진화로 한 번 더

실제 촬영본(시트 4장·QR 36개)에서 1단계만으로는 6개, 세 단계를 다 거치면
**36개 전부**가 읽혔습니다. 동영상·카메라 프레임은 속도가 중요하므로 1단계만
씁니다 — 어차피 다음 프레임이 곧 옵니다.

### 파운틴은 막히면 소거로 풉니다

peeling 으로 풀다 막히면 **남은 방정식을 GF(2) 위에서 직접 소거**합니다.
peeling 은 차수 1짜리 조각이 끊기면 멈추지만, 방정식이 미지수만큼 독립이면
이쪽은 풉니다.

소거는 끝까지 기다렸다가 하지 않고 **스캔 도중에도 주기적으로 두드려 봅니다.**
peeling 이 40/97 에서 멈춰 있어도 방정식은 이미 다 모여 있는 경우가 흔하기
때문입니다. 비용이 O(n²) 이라 실패하면 다음 시도까지의 간격을 두 배로 벌리고,
미지수가 600개를 넘으면 스캔 중에는 손대지 않습니다. 덕분에 같은 영상에서
필요한 패킷이 129개에서 102개로 줄었습니다.

### 인코더를 직접 만든다면

**seed 는 32비트 전 구간에서 고르게 뽑아야 합니다.** 1, 2, 3 … 처럼 작은 값을
이어 쓰면 xorshift32 의 첫 출력이 전부 작은 수라서 차수가 1로 고정되고,
파운틴 코드가 쿠폰 수집 문제로 퇴화합니다. (실제로 이 함정에 빠뜨려 보니
패킷 3배를 넣고도 97블록 중 94개에서 멈췄습니다.)

## 검증 상태

헤드리스 Chromium(Playwright)으로 실제 복원까지 돌려 확인했습니다. 성공 사례는
모두 복원된 zip 의 **SHA-256 이 원본과 일치**했고, 콘솔 에러는 없었습니다.

| 시험 | 입력 | 결과 |
|---|---|---|
| **실제 촬영본** | 모니터를 폰으로 찍은 사진 4장 (QR 36개, 버전 25) | 36/36 · zip CRC 정상 · 162,628 B 파이썬 파일 복원 |
| **생성기 왕복 (시트)** | 만든 시트를 화면에 띄워 찍은 사진 2장 | 7/7 · SHA 일치 |
| **생성기 왕복 (스트림)** | 만든 재생기를 촬영한 동영상 | 10/10 · SHA 일치 |
| 시트 사진 | 9장 | 9/9 · SHA 일치 |
| 시트 사진 (2장 빠짐) | 7장 | 빠진 조각 번호를 정확히 보고 |
| 스트림 사진 | 30장 | 패킷 10개로 10/10 · SHA 일치 |
| 스트림 사진 (1/3 버림) | 20장 | peeling 정체 → 연립 소거로 10/10 · SHA 일치 |
| 스트림 동영상 (흔들림·초점흐림·노이즈) | 1280×720 · 17.5초 · 49KB zip | 97/97 · SHA 일치 |
| 카메라 | 가짜 카메라 장치로 QR 영상 주입 | 1.5초 만에 10/10 · SHA 일치 |
| 최소 여유분 | K=97 에 패킷 105개 (1.08배) | 연립 소거로 97/97 · SHA 일치 |
| 중지 버튼 | 긴 영상을 스캔 중 강제 중지 | 모은 조각으로 97/97 · SHA 일치 |
| 오프라인 | 서비스워커 등록 후 망 차단·새로고침 | 페이지가 뜨고 복원까지 정상 |
| QR 없는 사진 | 1장 | "QR 을 하나도 읽지 못했습니다" |
| 서브패스 배포 | `/kinescope/` | 정상 — 404 없음 |
| 연속 사용 | 시트 → 스트림 → zip 내려받기 | 상태 초기화·모드 전환·저장 모두 정상 |

또한 `lib/lt.js` 의 블록 선택(xorshift32 + Robust Soliton)이 파이썬 인코더와
비트 단위로 같은지 K=1~65535, seed 경계값 포함 **130/130 완전 일치**를
확인했습니다. 부동소수점 구현 차이로 갈리지 않도록 누적분포를 24비트 정수로
양자화해 두었습니다.

**아직 확인하지 못한 것**

- 아이폰이 찍은 실제 `.mov`(H.264/HEVC). 시험 환경에 그 코덱이 없어 VP8 로
  대신했습니다. 프레임을 뽑는 코드는 코덱과 무관한 `<video>` 경로라 그대로
  따라올 것으로 봅니다
- Safari 와 Firefox. Chromium 에서만 돌렸습니다. Firefox 는
  `requestVideoFrameCallback` 이 없어 재생 패스가 `requestAnimationFrame` 으로,
  훑기 패스가 고정 간격으로 물러섭니다(느리지만 동작합니다)
- 진짜 카메라로 찍은 **동영상**과 카메라 하드웨어. 사진은 실제 촬영본으로
  확인했지만, 동영상은 흔들림·초점흐림·노이즈를 합성해 대신했고 카메라는
  가짜 장치로 대신했습니다

### 회귀 시험 돌리기

```bash
npm i playwright && npx playwright install chromium
python3 -m http.server 8000 &
node tools/selftest.mjs http://localhost:8000/ <원본zip의 sha256> out/*.png
```

복원된 zip 의 SHA-256 이 기대값과 같고 콘솔 에러·404 가 없으면 `PASS` 와 함께
0을 돌려줍니다. 이미 받아둔 크로미움이 있으면 `CHROMIUM_PATH` 로 가리킬 수 있습니다.
