# Kinescope

화면에 흘려보낸 QR을 찍은 **동영상이나 사진**에서 원본 파일을 되살립니다.
브라우저 안에서만 돌고, 서버가 없고, 인터넷 없이 동작합니다.

키네스코프(kinescope)는 TV 화면을 필름 카메라로 찍어 방송을 보존하던 실제 기법입니다.
이 도구가 하는 일도 같습니다 — 화면을 촬영해서 내용을 되살리는 것.

## 왜 서버가 없는가

- **소스 코드가 서버로 올라가지 않습니다.** 이 도구가 다루는 게 남의 코드라는 걸
  생각하면, 업로드받는 설계는 그 자체로 부담입니다
- **인터넷 없이 동작합니다.** 망이 없는 곳에서 쓰는 게 원래 목적이니 이게 핵심입니다.
  라이브러리를 CDN이 아니라 `vendor/` 에 넣어둔 이유입니다
- 서버 비용과 운영이 없습니다

## 실행

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

`file://` 로 열면 **동작하지 않습니다.** ES 모듈 워커와 wasm 로딩이 차단됩니다.

### GitHub Pages 에 올리기

저장소 루트에 그대로 두고 Settings → Pages → Deploy from a branch → 루트(`/`)를
고르면 끝입니다. 주소는 `user.github.io/kinescope/` 가 됩니다.

- 모든 경로가 `import.meta.url` 기준 상대경로라 **서브패스에서도 깨지지 않습니다.**
  실제로 `/kinescope/` 아래에 올려두고 확인했습니다
- 루트의 빈 `.nojekyll` 파일을 지우지 마세요. 이게 없으면 Jekyll 이 일부 경로를
  건드려 `vendor/` 쪽에서 404 가 납니다
- `.wasm` 은 Pages 가 `application/wasm` 으로 서빙합니다. 설령 스트리밍
  인스턴스화가 실패해도 ArrayBuffer 방식으로 자동 폴백합니다
- HTTPS 라 `crypto.subtle` 도 정상 동작합니다

## 구조

```
index.html          화면 + 스타일
app.js              파일 입력, 동영상 프레임 추출, 결과 표시
lib/
  worker.js         워커: QR 디코드 + 조립 (메인 스레드 안 막음)
  lt.js             LT 파운틴 디코더 + 순번 수집기
vendor/
  zxing/            zxing-wasm 3.1.2 (리더 전용, 1.1MB wasm)
  fflate.js         zip 해제
tools/
  kinescope_encode.py   참조 인코더 — 시험용 QR을 만들어냅니다
  selftest.mjs          헤드리스 브라우저로 복원까지 돌려보는 회귀 시험
```

**두 형식을 자동으로 구분합니다.**

| 형식 | QR 본문 | 모으는 방식 |
|---|---|---|
| 스트림 | 바이너리 매직 `QS` | LT 파운틴 — 아무 조각이나 충분히 모이면 됨 |
| 시트 | `QRP001/036:` | 순번 수집 — 번호가 다 있어야 함 |

## 처리 흐름

동영상은 **두 패스**로 훑습니다.

1. **재생 패스** — `requestVideoFrameCallback` 으로 재생하며 프레임을 뽑습니다.
   빠르지만 디코더가 못 따라간 프레임은 흘려보냅니다. 대개 이것만으로 끝납니다
2. **훑기 패스** — 재생만으로 모자랐으면 한 프레임씩 seek 하며 다시 훑습니다.
   느린 대신 한 장도 놓치지 않습니다. 프레임 타임스탬프를 보고 같은 프레임은
   두 번 디코드하지 않으므로, 30fps 촬영본에서 10fps 화면을 찍었더라도 헛일이 없습니다

**충분히 모이는 즉시 멈춥니다.** 20초 영상이라도 중간에 끝나는 경우가 많습니다.

파운틴 스트림은 peeling 으로 풀다가 막히면 **남은 방정식을 GF(2) 위에서 직접
소거**합니다. peeling 은 차수 1짜리 조각이 끊기면 멈추지만, 방정식이 미지수만큼
독립이면 이쪽은 풉니다 — 짧게 찍은 영상이 여기서 자주 살아납니다.

조립이 끝나면 패킷 헤더에 실린 SHA-256 앞 4바이트와 대조해 **✓ 체크섬 일치**를
표시합니다.

## 화면

가운데 격자가 **블록 복원 현황**입니다. 한 칸이 원본 블록 하나이고, 워커가 보내준
번호대로 실제로 풀린 칸만 채워집니다. 후반부에 갑자기 우르르 채워지는 게 정상입니다
— peeling 디코더는 임계점을 넘는 순간 연쇄적으로 풀립니다.

실패하면 무엇이 부족한지 말해줍니다. 시트 방식은 **빠진 조각 번호**를, 스트림
방식은 몇 블록이 모자란지를 표시합니다.

## 검증 상태

헤드리스 Chromium(Playwright)으로 실제 복원까지 돌려 확인했습니다. 모든 경우에서
복원된 zip 의 **SHA-256 이 원본과 일치**했고, 콘솔 에러는 없었습니다.

| 시험 | 입력 | 결과 |
|---|---|---|
| 시트 사진 | 9장 | 9/9 · SHA 일치 |
| 시트 사진 (2장 빠짐) | 7장 | 실패를 정확히 보고 (빠진 조각: 8, 9) |
| 스트림 사진 | 30장 | 10/10 · SHA 일치 |
| 스트림 사진 (1/3 버림) | 20장 | peeling 정체 → 연립 소거로 10/10 · SHA 일치 |
| 스트림 동영상 | 960×720 화면 녹화 3초 | 10/10 · SHA 일치 |
| 스트림 동영상 (흔들림·초점흐림·노이즈) | 1280×720 · 17.5초 · 49KB zip | 97/97 블록 · SHA 일치 (14초) |
| 최소 여유분 | K=97 에 패킷 105개 (1.08배) | 연립 소거로 97/97 · SHA 일치 |
| QR 없는 사진 | 1장 | "QR 을 하나도 읽지 못했습니다" |
| 서브패스 배포 | `/kinescope/` | 정상 — 404 없음 |
| 연속 사용 | 시트 → 스트림 → zip 내려받기 | 상태 초기화·모드 전환·저장 모두 정상 |

또한 `lib/lt.js` 의 블록 선택(xorshift32 + Robust Soliton)이 파이썬 인코더와
비트 단위로 같은지 K=1~65535, seed 경계값 포함 **130/130 완전 일치**를 확인했습니다.
부동소수점 구현 차이로 갈리지 않도록 누적분포를 24비트 정수로 양자화해 두었습니다.

**아직 확인하지 못한 것**

- 아이폰이 찍은 실제 `.mov`(H.264/HEVC). 시험 환경에 그 코덱이 없어 VP8 로 대신했습니다.
  프레임을 뽑는 코드는 코덱과 무관한 `<video>` 경로라 그대로 따라올 것으로 봅니다
- Safari 와 Firefox. Chromium 에서만 돌렸습니다. Firefox 는
  `requestVideoFrameCallback` 이 없어 재생 패스가 `requestAnimationFrame` 으로,
  훑기 패스가 고정 간격으로 물러섭니다(느리지만 동작합니다)
- 진짜 카메라로 찍은 영상. 흔들림·초점흐림·노이즈를 합성해 대신했습니다

## 시험용 QR 만들기

```bash
pip install segno
python3 tools/kinescope_encode.py stream payload.zip -o out/   # 파운틴 프레임
python3 tools/kinescope_encode.py sheet  payload.zip -o out/   # 순번 시트

ffmpeg -start_number 0 -framerate 10 -i out/frame_%05d.png \
       -pix_fmt yuv420p out/stream.mp4
```

인코더를 직접 만든다면 **seed 는 32비트 전 구간에서 고르게 뽑아야 합니다.**
1, 2, 3 … 처럼 작은 값을 이어 쓰면 xorshift32 의 첫 출력이 전부 작은 수가 되어
차수가 1로 고정되고, 파운틴 코드가 쿠폰 수집 문제로 퇴화합니다. (실제로 이 함정에
빠뜨려 보니 패킷 3배를 넣고도 97블록 중 94개에서 멈췄습니다.)

## 회귀 시험 돌리기

```bash
npm i playwright && npx playwright install chromium
python3 -m http.server 8000 &
node tools/selftest.mjs http://localhost:8000/ <원본zip의 sha256> out/*.png
```

복원된 zip 의 SHA-256 이 기대값과 같고 콘솔 에러·404 가 없으면 `PASS` 와 함께
0을 돌려줍니다. 이미 받아둔 크로미움이 있으면 `CHROMIUM_PATH` 로 가리킬 수 있습니다.
